Privacy Policy

TFT Improvement System is designed to keep player training data on the player's own device.

Effective date: August 3, 2026 · Version 1.0

1. Scope

This Privacy Policy describes how TFT Improvement System handles information in the public website, browser prototype and planned OW-Electron desktop application. The project is maintained by the GitHub user VictorGTheCoder.

2. Local-first design

The current prototype does not require an account and does not operate a central player database. Training records are stored on the user's device unless the user explicitly exports them.

3. Information stored by the browser prototype

The browser prototype may store the following information in browser local storage:

  • training objectives;
  • match references and placements entered by the user;
  • decision context, alternatives, predictions, outcomes and learning principles;
  • review notes and status;
  • spaced-repetition drills and answers;
  • watchlist entries and application settings;
  • local audit and data-integrity information.

This information is not automatically transmitted to the project maintainer.

4. Planned Overwolf capture information

After approval and technical validation, the desktop application is intended to passively collect supported information belonging to the local player, including:

  • game, match and round transitions;
  • stage, health, gold, level, experience and placement;
  • the local player's board, bench, items and shop when supported;
  • combat results and local-player damage when supported;
  • technical diagnostics required to identify missing or malformed events.

Experimental capture data is stored in a separate local file. The current capture engine limits storage to the most recent 50 sessions and 500 redacted diagnostic entries.

5. Information excluded by design

The application is not intended to collect or retain:

  • opponent boards or benches;
  • automated scouting or opponent-action histories;
  • prohibited augment or Legend performance data;
  • Riot account credentials;
  • payment-card details;
  • advertising identifiers in the current prototype.

Unsupported or prohibited event payloads are rejected. Diagnostic entries identify that an event was filtered without retaining its raw content.

6. Public website

The public website does not intentionally use analytics scripts, tracking pixels, marketing cookies or third-party fonts. It is intended to be hosted through GitHub Pages. GitHub may process standard connection and security logs under GitHub's own terms and privacy policies.

7. Riot Games API and account access

The current product does not call the Riot Games API and does not use Riot Sign On. The Production application is being registered because the product serves TFT players and is planned to integrate with the game through Overwolf. If Riot API or Riot Sign On access is added in the future, this policy and the product registration will be updated before that feature is released.

8. Advertising and subscriptions

The current website and prototype contain no advertising. A future public Overwolf release is intended to use only Overwolf-supported monetization, outside active gameplay. Overwolf and advertising partners may process information under their own policies. This Privacy Policy will be updated with the final implementation before monetization is enabled.

9. Export, deletion and retention

Users control the data stored by the application:

  • browser records can be exported as JSON or CSV;
  • individual records can be edited or deleted;
  • all browser records can be removed from the application's Data screen or by clearing site data;
  • desktop capture records can be removed by deleting the local capture file or uninstalling the application after removing local data.

Because the current project does not maintain a central player database, the maintainer generally has no copy to retrieve or delete on the user's behalf.

10. Security

The project uses data minimization, an explicit event allow-list, separation between raw capture and learning records, redaction of rejected payloads and local storage by default. No system can guarantee absolute security, so users should export backups carefully and avoid entering sensitive personal information in free-text fields.

11. Children

The product is not directed to children under 13 and does not knowingly collect personal information from children through a central service. A parent or guardian who believes personal information has been submitted to a future hosted service should contact the maintainer.

12. Changes

Material changes will be published on this page with a new effective date. Changes involving Riot data, account access, remote storage or monetization will also be reflected in the Riot Developer Portal product registration before release where required.

13. Contact

Privacy questions and deletion concerns can be submitted through the project's public GitHub issue tracker. Do not include passwords, authentication tokens or other sensitive information in a public issue.
